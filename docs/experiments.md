# 实验记录与已知局限

记录截至 experiment_snapshot.json 的 UTC 时间；不是自动更新的监控页。

## 已验证

- 原项目四卡 full-model 运行，模型+Adam checkpoint 保存与新进程恢复；2000 步定期 checkpoint 已完成。
- 每卡 BS=4 在默认 allocator 下 OOM；BS=2、GA=8 全局64，实际分配峰值约54.1 GiB/卡。
- 固定已缓存 batch 更新约17秒；真实数据还包含 FFmpeg 和逐条 VAE 编码，初始约63–81秒，源文件 I/O 会使耗时波动。
- 同 checkpoint、同64条视频/时间/噪声对照8次更新：全参数2e-6，RF loss 4.431511→4.429427（-0.047%）；新分组LR 4.431511→4.362955（-1.547%）。
- H3 直接解码有规则网格：同一视频 direct MSE 0.170343，官方空间+时间融合降到0.008701。不能用错误的直接解码基线判断预训练VAE质量。

## 数据错误

原训练1536步发生一次H.264 Invalid NAL unit size：坏片段只解出24帧，帧数检查拒绝并补入其他样本；实际采用的64条视频复查均无decode错误、像素SHA一致。当前读取器按退出码和精确帧数判断失败；它不是覆盖所有损坏视频的内容质量检测器。视频数据和逐样本日志未上传。

## 导出边界

独立导出更换Python包路径和准备器/启动路径，目标函数与模型数学不变；checkpoint包装器仅保留PiD使用的严格模型/Adam接口。没有对独立导出重新启动完整GPU训练，保留CPU测试与原实验full-model实测的区别。不要把原项目run config直接交给新包强行resume：源码hash及挂载路径契约不同，需显式迁移和验证。

精简导出不包含完整第三方工程与大文件，PiD 仅保留 PidNet 的实际运行依赖；Diffusers 改为 requirements.txt 安装的0.41.0。原full-GPU结果来自本地0.40.0.dev0快照，必须保留这项环境差异，先运行两步GPU检查。
